## 这个专题解决什么

在质量、安全和可验证性不下降的前提下，减少 Codex 与外部协作者对同一材料的重复阅读和无效往返；同时避免为了协作而把项目目录变成完整聊天、日志与 session 的副本。

## 讨论基线

专题形成时，项目已经具备受控的外部协作 harness、主题/session 注册、expected outcomes、回滚、能力探测和 provider 路由（见 `14a8985` 及其前后实现）。审计确认的主要缺口是：`collaborate.py` 会将完整 provider result 打印回调用端；没有紧凑回传协议、可恢复的批处理管线或基于对照实验的效能路由。该基线不是“项目永久版本号”，而是理解本方案问题定义的固定参照。
