# DEC-20260729-collaboration-efficiency

- 状态：accepted（方案与治理）；implementation planned（P0/P1/P2）
- 日期：2026-07-29
- 受影响主文档：产品需求文档、技术方案文档、实施计划文档、测试用例文档、迭代记录

## 上下文

双 Agent 协作可以让 Codex 不读取大量本地材料，但当前执行器会把完整 provider result 打印回调用端；同时，跨 Agent 需要最小共享状态，却不应把项目目录变成 transcript 与日志的复制库。

## 决策

采用统一的协作效能优化：以可验证交付质量为中心，联合控制紧凑回传、持续上下文、最小协作持久化、批处理、风险复核、路由、总成本和完成效率。

项目产物是事实唯一来源。长期协作层只保留稳定背景、确认决策、短 topic 状态和本机 session 映射；完整 handoff、输出、日志和快照属于带保留期的 runtime cache。主文档持续更新；重大取舍使用 DEC 记录版本化；Git 历史用于逐字追溯。

## 备选方案

1. 仅增加 token 上限：无法保证质量、避免结果回流或解决持续交接问题。
2. 将所有 session/transcript/日志长期保存到项目目录：可恢复性高，但重复、隐私、查询和维护成本不可控。
3. 每次优化复制整份 PRD/技术方案：版本可见但容易形成多份冲突的“当前规则”。

## 后果与实施

P0 先实现紧凑回传和结果 schema；P1 再实现可抽样、可恢复的 batch；P2 以 Codex-only 对照校准路由。未完成 P0 前，不扩大大批材料的自动外部协作。对应测试为 TC-36 至 TC-43。
