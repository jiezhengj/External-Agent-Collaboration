### 真实验证与发现

- MiMo 与 DeepSeek 均通过创建 session、精确 `--resume`、受控文件编辑 smoke test。
- 初次 MiMo session 未获得 `Write`，原因是该 session 在执行器添加 `Write` 前创建；恢复时保留其初始工具集。
- 新建的 MiMo ephemeral session 与 DeepSeek ephemeral session 均已实测支持原生 `Write`。
- 对旧 MiMo session，精确 `touch <允许路径>` 加 Edit 的 Bash 兜底成功；不需要开放任意 Bash。这是通用 session 陈旧兜底的验证样本，不是 MiMo 特例或硬编码。

### Expected outcomes 实施

- 新增 execute 必填的 JSON outcomes 契约，支持文件存在/内容、变更数量、受限验证命令和受限 JSON Schema。
- 执行器不再以模型最终文本作为成功依据；任一 outcome 失败会恢复该次任务变更并标记 failed。
- 完成了未传 outcomes 的调用前拒绝、本地失败回滚以及 MiMo 真实成功路径验证。

### 自动分类、学习路由与生命周期实施

- 新增确定性的 `classify_task.py`：对敏感、实时/连接器、原生成品、简单任务和复杂本地协作给出可复现的 delegation 决策。
- 新增 `provider-metrics.json` 与 `provider_routing.py`：不保存提示词或文件正文；冷启动按 task type/mode 轮换，达到最小样本后按质量、完成率和耗时选择。
- `collaborate.py` 不再用“现有 session 数量”选择新主题 provider，并将每次调用的匿名结果元数据自动入账。
- 调用账本同时记录 CLI 返回成本；`assess_run.py` 可在 Codex 评估或用户采纳后按 run ID 回写质量分、采纳和返工次数，且不保存理由或内容正文。
- 新增 `topics.json` 自动登记、新 session fork 和 `archive_session.py`。使用 MiMo 的真实只读 smoke 已验证 `--resume <id> --fork-session` 会获得不同 session ID；测试 fork 随后已归档。
- execute 若 outcomes 指向尚不存在的文件，执行器会自动检查/更新能力档案；恢复 session 缺少 Write 时自动 fork，原生 Write 实测不可用才使用精确 Bash 创建兜底。
- 已通过 `test_classify_task.py`、`test_provider_routing.py`、`test_session_lifecycle.py`、`test_outcomes.py` 与 Python 语法校验。

### 一次性独立审查与非代码边界

- 新增按代码/文档研究/创作/数据/个人建议划分的交接模板；明确最终富文本办公文档、图片、表格、演示、PDF、当前信息和连接器数据留在 Codex 原生路径。
- `test_review_execution.py` 已通过。

### 协作效能优化方案

- 审计结果确认：现有外部协作可以让 Codex 不读取大本地材料，但 `collaborate.py` 仍会把完整 provider result 打印回调用端，缺少返回长度和批处理协议。
- 将原 Token 方案重构为 `docs/专题/2026-07-29-协作效能优化/方案.md`：以可验证交付质量为中心，统一规划紧凑回传、持续上下文、风险复核、批处理、路由、总成本与完成效率。
- 方案新增最小协作持久化层：项目产物为事实来源；只长期保留稳定背景、决策、短 topic 状态和本地 session 映射；handoff、输出、日志和快照为带保留期的 runtime cache。
- 10,000 × 1 MB 的场景不得单次 execute；现有全项目快照上限会拒绝，应使用只读 batch 与小范围写入批次。
