# 外部代理持续协作 Skill：测试用例

## 1. 测试范围

覆盖 Skill 发现、配置诊断、会话生命周期、路由、CLI 调用、自动文件修改、越界拦截、隐私与故障恢复。真实 provider 测试需在用户授权后执行；其余用 fake launcher 完成。

## 2. 用例

|编号|场景与输入|期望结果|
|---|---|---|
|TC-01|从项目根目录启动 Codex，提出“继续与 provider A 协作处理品牌策略”|Skill 可发现；解析或提示选择对应 session。|
|TC-02|普通简单改写请求|Skill 不隐式触发，Codex 直接回答。|
|TC-03|新主题、未指定 provider|在健康 provider 间按持久化公平轮换选择，创建 registry 与 handoff。|
|TC-04|同主题存在唯一 provider A session|调用命令带精确 `--resume <id>`，不得使用 `--continue`。|
|TC-05|同主题存在多个 session|停止并返回候选，不随机恢复。|
|TC-06|用户指定 provider B，存在 provider A session|新建或使用 provider B session，绝不复用 provider A ID。|
|TC-07|provider A profile 缺失|`doctor.py` 返回缺失项目名，不暴露或猜测凭证。|
|TC-08|CLI 返回合法 JSON 与新 session ID|原子更新 `sessions.json`，写入输出和审计记录。|
|TC-09|CLI 返回无效 JSON、任务失败或 outcome 失败|记录失败；不污染 registry；不跨 provider 重试。|
|TC-10|主 provider 认证、余额、端点或暂时服务不可用|只记录脱敏 failure kind 和 retry time；最多启动一次另一健康 provider；两个结果均记录。|
|TC-11|`execute` 修改允许目录中的 Markdown|快照、修改清单、diff 和输出记录齐全。|
|TC-12|`execute` 试图写 `.env` 或 `secrets/`|脚本拒绝，目标文件不变。|
|TC-13|`execute` 试图执行 `git push`/`git reset`|命令策略拒绝，日志标记禁止行为。|
|TC-14|修改范围超出 handoff 的允许目录|后置 diff 检查标记 `needs_review`，不报告成功。|
|TC-15|交接包含 token、私钥或客户导出|预检拒绝创建调用并提示移除敏感内容。|
|TC-16|高风险代码改动完成|Codex 检查完整 diff 并运行项目规定的验证命令。|
|TC-17|一个 session 由 provider A 长期恢复|配置目录、topic 与 provider 始终一致。|
|TC-18|同一主题改模型配置或工作目录|拒绝恢复原 session，要求新建或 fork。|
|TC-19|首次需要新建文件、能力档案不存在|运行 ephemeral capability probe，并记录原生 Write 是否实际创建成功。|
|TC-20|能力档案未过期且 CLI/profile 未变|跳过 probe，不产生额外 provider 调用。|
|TC-21|模型报告缺少 Write 工具|立即运行 probe；若原生 Write 不可用，使用最小 Bash 白名单创建并更新档案。|
|TC-22|旧 session 的 initial_toolset 不含 Write，但 provider 新会话支持 Write|不把 provider 结果套用给旧 session；使用精确 Bash 兜底或显式 fork/new session。|
|TC-23|execute 未传 expected outcomes|在调用 provider 前拒绝请求。|
|TC-24|外部模型返回成功但文件内容不符合 `file_equals`|执行器返回 failed 并恢复本次任务变更。|
|TC-25|`command_succeeds` 未列入 validation allowlist|拒绝 outcome；不执行该命令。|
|TC-26|复杂代码执行、实时天气、PPTX、token、简单改写|分类分别为 external、native、native、prohibited、direct。|
|TC-27|任意外部可委派的新主题|健康 provider 严格交替，输出对应的 `starter_policy_*_rotation`。|
|TC-28|同类任务两家均有人工质量分结果|仍按公平轮换；指标只供审计和未来明确启用的学习策略使用。|
|TC-29|从 active session 运行 `--fork-session`|真实 CLI 返回新 ID；父子 session 均登记且父 session 不被覆盖。|
|TC-30|execute outcome 指向不存在文件且恢复 session 缺 Write|能力档案有效时自动 fork；探测失效时先探测再执行。|
|TC-31|归档 active session|session/topic 索引状态更新，生成非敏感 archive handoff。|
|TC-32|execute 新增符号链接或未声明二进制文件|清单检测并恢复，状态不得为 completed。|
|TC-33|execute 删除允许目录中的旧文件但未传 `--allow-delete`|检测、恢复并标记 needs_review。|
|TC-34|项目快照超过 500 MiB|调用前拒绝，要求缩小工作目录或执行范围。|
|TC-35|completed 高风险 execute|`review_execution.py` 只调用另一 provider 一次做 read-only critique，不回调执行者。|

|TC-36|外部 provider 返回超过 compact 上限|完整 result 仅落本地 runtime；Codex 只接收不超过 8 KiB 的 compact envelope、截断标记与路径。|
|TC-37|外部结果不符合受限 response schema|记录 `result_contract_failed`；仅剥离严格最外层 JSON fence 后可恢复为 structured；不以模型文本替代 outcomes，也不自动重复同一 consult。|
|TC-38|长持续主题完成多轮后恢复|只读取短 topic 状态、决策与本机 session 映射；不加载完整 transcript；topic state 不超过一页。|
|TC-39|大量非敏感文本的 batch dry-run|生成 manifest、样本 batch 和 JSONL schema；未达抽样质量阈值不得扩展全量。|
|TC-40|batch 中断后恢复|source hash 与 schema version 未变化的记录不重复处理；失败清单可独立重试。|
|TC-41|超出 execute 快照上限的大材料任务|拒绝单次 execute，建议只读 batch 或拆分为小范围写入批次。|
|TC-42|高风险 batch 出现异常或抽样不一致|只对异常/样本触发一次独立审查，不让第二 provider 重读全部材料。|
|TC-43|新增实质优化需求|存在对应专题入口（含讨论基线、实施状态和证据）、DEC 记录、受影响主文档更新、迭代记录和验证证据；无重复完整文档版本或孤立顶层专题文件。|
|TC-44|全局可发现时提出“审查整个仓库的鉴权实现”或“实现这个模块及所有关联调用”|`SKILL.md` 元数据作为 Skill 发现信号而被选中；随后才运行分类、配置检查和路由。|
|TC-45|全局可发现时提出普通问答、常规评审或小型单文件修改|`SKILL.md` 元数据不应选中本 Skill；Codex 直接处理。|
|TC-46|Skill 已被选中但本地 provider 配置不可用|不得发起外部 CLI 调用；返回或记录明确的本地配置诊断，不能猜测 provider 或凭证。|
|TC-47|活跃 session 的 provider 正处于 health 冷却|不迁移该 session；自动调用使用另一健康 provider 的新 session，并记录 source session key。|
|TC-48|余额/认证/端点故障、限流/传输/服务端故障|分别写入 24 小时、5 分钟至 6 小时的脱敏冷却；无后台探测。|
|TC-49|profile 含 `ANTHROPIC_MODEL` 与 FABLE/OPUS/SONNET/HAIKU/SUBAGENT 环境映射|runner 注入环境但命令不含 `--model`，不干预 provider 内部模型或子代理。|
|TC-50|profile 无用户批准记录，或 endpoint/模型映射/config dir/非密钥 environment 发生变化|runner 在启动 Claude Code 前拒绝；无 provider 请求。|
|TC-51|`dontAsk` 返回 `permission_denials`|状态为 `blocked_by_permission`，不等待不可操作的终端审批，也不得报告 completed。|
|TC-52|Windows 上执行 `command_succeeds`|使用与 `--validation-argv` 相同的 JSON 参数数组、`shell=False` 执行并返回 0；不依赖 `true` 等 Unix 命令。|
|TC-53|Windows 与 macOS 各有平台 local profile|各自读取对应的直接 `auth_token`、launcher 和 `config_dir`；不得要求环境变量、Keychain 或 Credential Manager。|
|TC-54|Windows 读取 macOS session/capability 记录|不得匹配或恢复该 session；旧能力记录视为过期；迁移 dry-run 报告 foreign record。|
|TC-55|同一份 `providers.shared.json` 在模拟 Windows 与 macOS 主目录加载|`config_dir_relative_to_home` 分别解析到各自主目录；逻辑 `claude` launcher 保持由 PATH 解析。|
|TC-56|版本化 shared profile 含 `auth_token`、绝对目录或 `.exe` launcher|加载器在外发前拒绝；直接 token 只能出现在 Git 忽略的平台 local profile。|
|TC-57|legacy profile 含直接 token，运行当前平台迁移|token 复制到当前平台 Git 忽略的 local profile；shared 不含 token；两端平台 profile 未就绪时拒绝清理 legacy。|
|TC-55|旧 session 缺 Write 且当前主机未确认 POSIX shell|不得生成 `touch`/`mkdir -p`；要求 native Write、fork 或新 session。|

## 3. 验证命令

- `python3 -m py_compile`（macOS/Linux）或 `py -3 -m py_compile`（Windows）：验证 Python 脚本语法；受限目录不能写入 `__pycache__` 时，改用不写入源码树的解析检查。
- `quick_validate.py`：验证 Skill frontmatter、命名与目录。
- fake launcher：验证参数、JSON、超时、失败和文件修改路径。
- `git diff --check`：若项目进入 Git 管理，检查空白错误。
- 最小真实 smoke test：仅在用户允许消耗额度时运行一次无敏感只读调用；不为 Claude Code 内部子代理单独 probe 或周期验证。

## 4. 退出准则

所有非真实网络用例在 Windows 与 macOS 通过；敏感路径和禁止命令拦截通过；Skill validator 与 Python 语法检查通过；跨平台 session 不恢复、能力记录不复用；已配置的真实 profile 完成创建、恢复、受控编辑和新会话 capability probe。协作效能相关用例在对应 P0/P1 实现后纳入退出准则。
