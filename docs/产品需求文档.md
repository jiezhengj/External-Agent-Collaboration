# 外部代理持续协作 Skill：产品需求文档

## 1. 背景与目标

本项目要在 Codex 桌面端中提供一个项目级 Skill，使 Codex 能把适合的工作自动交接给通过 Claude Code CLI 运行的、本地配置的外部 provider，并在后续请求中恢复同一协作主题的会话。

这不是一次性子代理，也不是多代理自动辩论。Codex 是用户的统一入口与协调者；本地配置的外部 provider 是各自保有项目会话的协作代理。每次外部调用对应用户请求或 Codex 的一次明确协作步骤，结果回到 Codex 后再继续对话。

首版必须同时具备：

- 自动判断何时调用外部协作者；
- 自动选择或恢复正确的协作者会话；
- 对授权任务允许外部代理修改项目文件；
- 保存可读、可恢复的协作状态；
- 对高风险行为保留机械约束与可审计记录。

## 2. 用户与场景

|场景|期望行为|
|---|---|
|延续一个品牌、写作或技术主题|匹配主题、供应商、模型配置与工作目录，恢复准确 session。|
|陌生项目或大量本地资料分析|自动建立会话、交接限定资料，输出结构化结论。|
|需要实际落地的代码、文档或文件改动|外部代理在授权范围内修改；Codex 读取变更、运行规定校验并向用户说明。|
|需要另一种观点|保留协作者的独立产出，不强制再让其他代理自动反驳。|
|时效信息、连接器数据或原生成品|优先 Codex 的网页、连接器、图像、文档、表格等原生能力，不调用 CLI 协作者。|

## 3. 范围

### 3.1 包含

- 项目级 `external-agent-collaboration` Skill。
- 可配置 provider 的确定性启动 profile。
- `consult`、`continue`、`draft`、`critique`、`execute` 五类动作。
- 按持续主题管理的 Claude Code session ID。
- 交接包、输出、会话记录、执行日志和变更快照。
- 自动委派、自动恢复、自动输出归档；一次调用完成后返回 Codex。
- 外部代理在显式授权的任务范围内读取、编辑文件和运行有限命令。

### 3.2 不包含

- 自动修改 CC Switch 的全局当前供应商。
- 在不同 provider profile 之间复用同一 Claude Code session。
- 外部代理提交、推送、部署、发布、改写 Git 历史、安装全局包或读取密钥。
- 无用户请求或无 Codex 决策触发的后台循环、自动辩论或递归代理调用。
- 将完整 Codex 聊天记录、ChatGPT Memory、连接器数据或不相关文件发送给外部模型。

## 4. 核心需求

### R1：自动协作决策

Skill 隐式调用保持开启。Codex 在任务满足下列任一条件时可自动委派：已有主题会话可延续；需要本地大量文件上下文；需要独立方案或审查；需要限定范围的多文件执行；或外部协作者的既有主题认知会显著降低交接成本。

不适合委派的任务必须由 Codex 直接处理或使用原生工具：简单问答/改写、实时事实未核验的研究、连接器私有数据、图像或办公成品制作、以及敏感内容。

### R2：会话连续性

每条会话绑定 `topic + provider + model_profile + working_directory + initial_toolset`。首次调用保存 CLI 返回的 `session_id` 与创建时工具集；同主题后续调用只能使用 `--resume <session_id>`。主题明显变更、模型配置变更或供应商变更时创建新会话；分支方案使用 fork，而非污染原会话。

### R3：确定性供应商启动

每个供应商由独立 launcher 和独立 `CLAUDE_CONFIG_DIR` 启动。Skill 不得通过切换 CC Switch 全局状态选择模型。当前项目采用用户明确授权的本地 `.ai-collaboration/providers.local.json` 直接 token 配置；该文件必须被 `.gitignore` 排除，且 token 不得写入版本化文件、会话注册表、交接包、日志或外部提示词。将来可替换为环境变量或钥匙串，但不能改变运行时 profile 隔离原则。

### R4：受控外部修改

`execute` 可由 Skill 自动选择，但仅在任务明确需要落地且工作区符合条件时启用。执行前必须：确认允许目录、检查敏感路径、记录文件快照、生成最小命令白名单。执行后必须记录外部结果、变更文件、命令结果与校验结果；Codex 根据风险检查 diff、测试或输出清单。

### R5：共享协作材料

项目内 `.ai-collaboration/` 保存稳定背景、当前状态、已确认决策、交接包、输出和会话注册表。它是跨聊天和会话的恢复媒介；外部 session 只是补充，不能成为唯一事实来源。

### R6：路由规则

用户明确指定 provider 时必须尊重。否则优先恢复主题已绑定的供应商；新主题在缺乏本地表现数据时按平衡轮换选择。记录任务类型、动作、耗时、完成情况、返工和错误原因，后续按真实记录调整路由，不把供应商宣传当作能力事实。

## 5. 风险分级与完成标准

|风险|例子|处理|
|---|---|---|
|低|头脑风暴、草稿、只读分析|自动交接，保留结果。|
|中|本地文档重写、普通代码修改|允许 execute；执行前快照，执行后检查范围与规定校验。|
|高|安全、架构决策、公共 API、迁移|可自动咨询或执行，但 Codex 必须验证关键结论、完整变更与相关测试。|
|禁止|密钥、生产数据、部署、Git 历史|Skill 直接拒绝外部交接或降级为不含敏感内容的协作。|

一次协作完成的标准：交接包可追溯、session/profile 可定位、输出或修改落盘、所需校验有结果、失败原因可见、Codex 向用户说明协作者贡献和未解决风险。

## 6. 验收标准

1. 用户以自然语言提出连续任务时，Skill 能隐式触发并恢复匹配的会话。
2. 新主题自动创建注册记录；同主题不会因“最近会话”而串线。
3. 不同 provider 的 session、配置目录和日志可区分。
4. `execute` 能在允许路径内修改文件并保存前后快照；越界、敏感路径和禁止命令会被拒绝。
5. 外部 CLI 故障时，最多对另一供应商故障转移一次；不会无限重试。
6. 未配置 profile 时，Skill 以明确的诊断信息停止，不猜测端点、模型名或凭证。
7. 首次需要新建文件/目录、能力记录过期、CLI/profile 变化或报告工具缺失时，Skill 运行 ephemeral 能力探测；普通任务不会重复探测。

### R7：协作效能与最小持久化

Skill 必须以可验证交付质量为中心，同时控制 Codex 上下文回流、外部调用成本、完成时间和重复阅读。外部协作者可以直接读取授权的本地材料，但 Codex 默认只接收紧凑状态、outcomes、变更/异常路径和短摘要；完整 provider 输出仅本地落盘并按需读取。

跨 Agent 长期共享的信息只包括稳定背景、已确认决策、每个活跃主题的一页短状态和本机 session 映射。项目源码、文档、数据、测试和 Git 历史是事实唯一来源；handoff、原始输出、日志和快照属于可清理 runtime cache，不得演化为第二套项目知识库。大批材料只有在可分片、可结构化验收、可抽样且 Codex 无需逐字复核时才可外部 batch。

## 7. 文档治理与版本策略

产品需求、技术方案、实施计划和测试用例是**持续更新的主文档**：始终描述当前有效规则，不为每一次优化复制完整版本。每次实质变更同时更新受影响主文档，并在 `docs/迭代记录.md` 记录日期、动机、影响、验证和迁移事项。

对存在明确取舍、需要长期追溯或可能被推翻的决定，新增短决策记录 `docs/决策记录/DEC-YYYYMMDD-<slug>.md`，包含状态、上下文、决策、备选方案、影响的主文档和废止关系。Git commit/tag 提供逐字历史；只有发布里程碑、对外接口/schema 变更或重大基线冻结时才给主文档标注版本号。

一次有明确问题、讨论基线和后续实施的优化，不直接作为顶层 `docs/` 文件保存，而是使用 `docs/专题/YYYY-MM-DD-<slug>/`。专题入口必须声明：固定讨论基线（提交、版本或其他可定位证据）、状态、关联 DEC、受影响主文档、实施/测试证据和替代或归档关系。专题方案记录当时的假设与分期；当前有效规则仍只写入四份主文档。
